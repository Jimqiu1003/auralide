## 1. 目标、事实与术语

目标是交付 AI-native HTML Presentation Editor：人和 Agent 共享结构化模型与命令，支持直接操作、可靠本地文档及 HTML 表达能力。
下一阶段先得到一个稳定、可验收的编辑产品，再逐步连接 Agent、版本恢复和受控扩展。原始 HTML 不成为第二个可写事实源。

术语：稳定基线指已合入 main 且通过验证的版本；原型指不承担正式能力承诺的实验；Proposed 指待决策设计。
里程碑完成要求代码、验证、人工验收及文档一致；实现但未合并标记 Implemented，未执行验证标记 NOT RUN。
会话 undo/redo、磁盘恢复备份、持久版本历史是三种能力，不能互相替代。

## 6. M3：推进 AI-native 的最小真实闭环

T12 / `feat/application-capabilities`：在有第二个真实调用方时提取共享 application 服务；UI、CLI、MCP 复用命令策略，Core 保持纯净。
先交付版本化扩展契约和一个内置适配器，复用现有模块；不同时开放第三方代码安装、通用插件市场或任意 docking。
T13 / `feat/agent-reviewed-apply`：Read→Propose→Diff/Preview→用户 Apply→结果审计→Undo；先一个适配器和一个文档范围。
Agent 身份、capability、session ID 与 expectedRevision 均由可信边界校验；origin 仅为溯源信息，不能充当凭证。
提案后人工编辑必须导致拒绝/重新生成，不能静默覆盖；删除、覆盖文件及第三方资源能力单独授权。
若一次提案有多条命令，先定义有界事务/历史分组及失败回滚，禁止部分成功后假报整次成功。
T13 在 Apply 前保留可核对的原文稿快照，支持拒绝、Undo 及恢复为副本；命名版本列表和跨重启版本管理仍留给 T14。
外部内容保持不可信；没有文件路径、任意 executeJavaScript、网络或密钥的隐式授权。密钥不进入文档、截图或审计。
通过本地确定性提案 fixture 验证策略，再做真实提供方调用；记录提供方/模型差异，不以模型输出稳定性代替系统测试。
退出场景：读取选中对象→提议改文案→审查→应用→撤销；拒绝、过期、越权、断连和重复请求均不损坏文稿。

## 7. M4：按产品目标扩展，逐项设门槛

- T14 / `feat/local-assets-versions`：先本地图像引用、路径安全与离线保存重开，再增加用户可见命名版本/恢复副本。恢复不能覆盖唯一现稿。
- 版本策略先定义磁盘预算、备份可发现性和恢复验证；不得静默删除历史。持久版本不同于无限保存 undo 快照。
- T15 / `feat/restricted-html-components`：为不能映射的 HTML/CSS/SVG/JS 设计显式受限组件。保留源码/资产、稳定 ID、转换报告与权限域。
- 原生对象通过 Core 编辑；不支持内容保持 opaque/preview-only。脚本执行是独立能力评审，不能由“已 sanitize”推出。
- T16 / `feat/export-pdf`：先 HTML 离线一致性及本地 PDF，再评估 PPTX 可编辑性/降级映射；输出兼容矩阵，不宣称任意 HTML 无损。
- T17 / `build/validated-desktop`：从验收提交重新构建 Windows 便携包并实测 EXE；macOS ARM64 原生 app bundle 单独验证。签名、公证、发布另立任务。
- 每项以 Issue + 窄范围设计启动；性能基线先于扩大规模。插件第三方安装和外部 Web Research 仅在权限/隔离验收后考虑。

## 8. 通用 gates、风险与第一批动作

| Gate / AC   | Given → When → Then                                                                          |
| ----------- | -------------------------------------------------------------------------------------------- |
| AC-001 底座 | 存在多标签/旧预览/未保存会话 → 执行 T01–T03 路径 → 状态、revision 与关闭语义符合约定         |
| AC-002 迁移 | 稳定 main 与来源 SHA 固定 → 迁入 A2/文件功能 → 无旧原型入口、无依赖缺项、原有边界测试通过    |
| AC-003 编辑 | 有合法及非法编辑请求 → 编辑/撤销/重做 → 内容正确、revision 单调；拒绝请求不变；导出/预览一致 |
| AC-004 演示 | 已保存多页文稿 → 开始/翻页/退出/重开 → 顺序正确、内容不变、上下文恢复                        |
| AC-005 授权 | 已审查提案 → 有权应用或过期/越权重放 → 仅授权且当前会话请求成功；人工修改不丢失              |
| AC-006 恢复 | 修改前快照或命名版本存在 → 恢复并保存副本 → 可核对内容且当前唯一文件不被破坏                 |
| AC-007 表达 | 支持/不支持 HTML 与本地资产 → 导入/重开 → 来源保留、损失可见、无脚本/资源越权                |
| AC-008 交付 | 已验收提交 → 导出/打包后离线打开 → 真实内容可用；能力声明与平台实测一致                      |

- 自动 gate：相关单元/负向回归 + `pnpm verify`；底座整合点至少一次 `pnpm exec turbo run lint typecheck test build --force`，明确缓存命中。
- 原生 gate：Windows x64 与 macOS ARM64，硬件/Node/Electron 身份、production/dev smoke、persistence；迁入后加 shell/file suite。macOS 关闭/activate 必须同一进程测试。
- UI gate：1280×800/1440×900、Light/Dark/System、键盘/焦点/模态层；物理缩放和屏幕阅读器由可用设备执行，缺失标记 NOT RUN，不编造 PASS。
- 规模 gate：先固定硬件和文稿 fixture，记录加载、100 次编辑/undo 的耗时与内存；为后续发布设明确预算后再宣称容量。20 MiB 文件限制不代表历史内存有界。
- 数据 gate：真实字节级冲突/取消/写失败；无 truncate fallback；备份可恢复；多进程竞态和断电耐久性限制继续明示。
- 流程 gate：每 PR 附 base/head SHA、来源、测试命令/结果、未验证项；P1.5/P2A Issue 随验收关闭，#10/#11/#18 保留独立 QA 决策边界。
- 首批仅启动 T01，然后 T02、T03、T04；执行前创建各任务记录，重查 PR/main 状态，不照抄今天的引用。
- 不删除旧分支/worktree。完成迁移、合并验证且确认无剩余工作后，才单独处理归档。
